# WeChat-Agent + 微信 4.1.10.27 接入教程

> 目标：在一台 Windows 10/11 x64 机器上装好 **WeChatAgent**（微信助手）、它的 **DSH 接入插件**、
> **微信 4.1.10.27 Hook 发送后端**，并能从微信里使用 DSH 人格聊天 / 助手任务 / 语音。
>
> 本教程对应的整合包在 `wechat-agent/` 目录；所有路径都以 WeChatAgent 安装根目录为基准：
>
> ```
> <安装根目录>/
> ├── app/          # WeChatAgent 程序（安装器放入）
> └── data/         # WeChatAgent 配置、缓存、运行数据（安装器创建）
>     └── workspace/   # 本项目运行目录（脚本、文档、packages、state）
> ```

## 0. 包内容

| 路径 | 用途 |
|---|---|
| `installers/WeChatAgent-Setup-0.4.1-x64.exe` | 官方安装包（含已授权的匹配微信 4.1.10.27 客户端与原生发送组件） |
| `integration-plugin/dsh-social-bridge-plugin/` | DSH 接入插件（微信 ↔ DSH 会话、工具授权、表情、搜索、任务…） |
| `integration-plugin/extension-runtime/` | 接入插件运行时所需模块 |
| `integration-plugin/wechat-deploy-plugin/` | 可选：把 Hook 的检查/准备/启动/重启/构建做成聊天工具 |
| `runtime/` | 安装后 `data/workspace` 的参考内容（scripts / docs / components / 配置示例） |
| `client-4.1.10.27/说明.md` | 微信客户端版本说明与校验方法 |

## 1. 环境要求

- Windows 10/11 x64，管理员权限（安装器、Hook DLL、ACL 固化需要）
- 至少 6 GiB 空闲磁盘（安装包 ~527 MB，安装后程序 + 客户端 + 数据约 2–3 GB，建议预留更多）
- [DeepSeek Harness 桌面版](https://www.deepseek.com/harness/)（单独安装，本包不包含）
- 一个用于登录微信的手机号账号（微信客户端 4.1.10.27，**不要升级**）
- 仅在需要重新构建原生 Hook 时才需要：Visual Studio C++ Build Tools、上游 Hook 源码
  （[aixed/WeChat-Hook](https://github.com/aixed/WeChat-Hook) 固定提交
  `e905d07ade50d2c6472e4eb3bd4f3fe19cf662c6`）

## 2. 安装 WeChatAgent

1. 以管理员身份运行 `installers/WeChatAgent-Setup-0.4.1-x64.exe`。
2. 选择一个安装根目录（例如 `D:\WeChatAgent`）。安装器按 `app\` + `data\` 布局写入，
   不要把它们拆到不同磁盘。
3. 安装完成后先不要启动；按第 3 步装好 DSH 再一起配置。

> 升级：先停止助手服务并从托盘完整退出旧版 WeChatAgent、DSH 和匹配微信，再运行新版安装器，
> 同位置升级会保留已有数据；换位置时按提示核对迁移来源与目标。

## 3. 安装 DeepSeek Harness

1. 从 [DeepSeek Harness 官网](https://www.deepseek.com/harness/) 下载安装桌面版。
2. 登录模型账号，完成初始化。
3. 记下 DSH 的数据目录（默认 `C:\Users\<你>\.dsh`），下一步接入插件会用到。

## 4. 安装接入插件（dsh-social-bridge-plugin）

WeChatAgent 安装器通常会自动把接入插件放进 DSH 可加载的位置；如果重装/迁移/需要修复，
用本包里的副本：

1. 把 `integration-plugin/dsh-social-bridge-plugin` 复制到
   `<安装根目录>\data\workspace\packages\dsh-social-bridge-plugin`。
2. 在 DSH 的 profile patch（`<DSH_HOME>\profiles\<profile>\cordis.patch.yml`）里增加一条
   insert 指向它的入口。参考该插件自带的 `cordis.patch.yml`，注意把
   `<WECHATAGENT_WORKSPACE>` 换成本机真实路径（例如 `D:/WeChatAgent/data/workspace`）。
3. 完整重启 DSH，确认插件加载成功（DSH 设置 → 插件列表里能看到 social bridge / WeChat 相关插件）。

> `extension-runtime/` 是接入插件的运行时依赖，按安装器生成的目录结构放好即可；
> 如果安装器已经管理好这些依赖，无需手动重复复制。

## 5. 首次配置（WeChatAgent 界面）

1. 启动 WeChatAgent（首次会进入配置向导）。
2. **打开匹配微信**：设置 → 微信与 DSH → 打开微信；用手机登录微信 4.1.10.27。
3. **连接并验证数据库**：选择读取方式，检测微信数据目录，验证数据库可读。
4. **添加允许的聊天**：在"聊天"页添加允许的好友 / 群（初始允许范围为空，需要手动加）。
5. **启动服务**：保存设置并启动助手服务。概览页应显示微信与 DSH 都是"正常/已连接"。
6. 此时安全边界：未加入允许列表的聊天不会触发模型；助手模式还有管理员与工具授权限制。

## 6. 部署 / 检查微信 Hook（4.1.10.27）

Hook 的作用：给微信客户端注入一个本机回环的发送后端（`127.0.0.1:30001`），
提供 `/WeChatAgent/health`、`/SendTextMsg`、语音/表情/文件发送等接口。**正常安装包已包含
已授权的匹配客户端与原生发送组件**，多数情况下只需"打开微信并检查"。

### 方式 A：用 wechat-deploy-plugin（推荐，可在 DSH 聊天里用）

1. 把 `integration-plugin/wechat-deploy-plugin` 放进
   `<DSH_HOME>/dsh-wechat-deploy-plugin`，并在 DSH profile patch 里加一条 insert（参考插件自带
   `cordis.patch.yml`，把 workspace 指向 `<安装根目录>/data/workspace`）。
2. 重启 DSH 后，在聊天里让 Agent 调用：
   - `wechat_deploy_status`：体检（版本、客户端、version.dll SHA、Hook 健康、进程、端口、托管服务）
   - `wechat_deploy_prepare`（confirm）→ `wechat_deploy_launch`（confirm）：准备并启动匹配客户端
   - `wechat_deploy_restart`（confirm）：只重启匹配客户端，不动桌面微信
3. 也可以不开 DSH，直接在插件目录执行：

```powershell
node tools/status-cli.mjs
```

### 方式 B：手动脚本（数据目录 `data/workspace/scripts/`）

```powershell
# 1) 准备匹配客户端：写入校验过的 version.dll 与本地令牌（不启动）
powershell -ExecutionPolicy Bypass -File scripts\launch-hook-wechat.ps1 -PrepareOnly

# 2) 确认桌面微信已从托盘退出，再启动匹配客户端并等待 Hook 就绪
powershell -ExecutionPolicy Bypass -File scripts\launch-hook-wechat.ps1
```

需要重新构建原生 DLL 时（一般不用）：

```powershell
# 上游 Hook 源码放在 data\workspace\components\WeChat-Hook（固定提交 e905d07a…）
powershell -ExecutionPolicy Bypass -File scripts\build-hook.ps1
# 产物：state\hook\native\version.dll + build.json
```

### Hook 健康的判定

```powershell
$token = (Get-Content '<安装根目录>\data\workspace\state\hook\native-token.txt' -Raw).Trim()
Invoke-RestMethod 'http://127.0.0.1:30001/WeChatAgent/health' -Headers @{ Authorization = 'Bearer ' + $token }
```

期望：`startupState=ready`、`version=4.1.10.27`、`integration=WeChatAgent-1`、
`backend=wechat-hook`、`pid` 属于匹配客户端。其它状态对照
`runtime/docs/HOOK_STARTUP_RECOVERY.md`。

## 7. 验证整条链路

1. 微信里给机器人发一条消息，确认有回复（聊天模式）。
2. 群聊需要 @ 或按群规则唤醒；未加入允许列表的聊天不会回复。
3. 让机器人发语音 / 点歌（若装了语音与点歌插件）确认语音发送正常。
4. 在 WeChatAgent 概览页看"最近记录"与诊断，确认发送回执正常。

## 8. 微信 4.1.10.27 客户端说明

- 本包**不包含腾讯微信客户端安装包**（版权原因，且本机没有对应版本安装器文件）。
- 上游 WeChatAgent 安装包已内置"维护者已授权的匹配微信 4.1.10.27 客户端与原生发送组件"，
  正常安装即可，不需要单独下载微信安装器。
- 如果你要**单独准备客户端**（例如从旧机器迁移），详见 `client-4.1.10.27/说明.md` 的校验步骤。
- **不要升级匹配客户端**：项目通过固定版本 + ACL 写保护 + 更新器禁用来降低版本漂移；
  升级后 Hook 需要重新适配与验证，不能只改配置里的版本号。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| Hook 不健康 / `BACKEND_UNAVAILABLE` | 检查匹配客户端进程、`127.0.0.1:30001`、version.dll 是否加载；看 `state/logs/hook-init.log` |
| `HOOK_VERSION_MISMATCH` | 匹配微信被升级/替换；恢复 4.1.10.27 客户端后重新 prepare + launch |
| `HOOK_AUTH_FAILED` | 本地令牌已刷新：完整退出匹配客户端再重新打开 |
| 端口被占用 | `runtime/docs/PORT_STARTUP_RECOVERY.md`；不要和另一个微信实例抢 30001 |
| 发送成功但对方没收到 | 核对实际发出记录与服务器消息 ID，超时先查再重试（见 `runtime/docs/SEND_QUEUE_RECOVERY.md`） |
| DSH 重启后插件没加载 | 确认 profile patch 的 `name` 指向真实文件路径、YAML 是合法数组；看 DSH 插件列表 |
| 桌面微信和匹配微信同时运行 | 启动匹配客户端前先从托盘退出桌面微信（脚本会拒绝混跑） |

更多文档在 `runtime/docs/`：`WECHAT_HOOK.md`、`INSTALLER_RELEASE.md`、`DATA_STORAGE.md`、
`EXIT_SHUTDOWN.md`、`DSH_CHAT_ACCESS.md`、`ASSISTANT_REMOTE.md`、`FILE_TRANSFER.md` 等。

## 10. 上传到 GitHub 的注意事项

`installers/WeChatAgent-Setup-0.4.1-x64.exe` 约 527 MB，**超过 GitHub 单文件 100 MB 限制**：

- 推荐把安装包作为 **GitHub Release 附件**上传（单文件上限 2 GB），仓库里保留
  `installers/SHA256SUMS.txt` 与说明。
- 或者用 Git LFS 跟踪：`git lfs install` 后按根目录 `.gitattributes` 对
  `wechat-agent/installers/*.exe` 生效，再 push（注意免费 LFS 配额）。
