# 微信文件通道

使用方法见 [助手模式](ASSISTANT_MODE.md)。先指定管理员，再为目标会话开启“微信文件收发”；聊天范围、管理员规则及 DSH 原生权限继续生效。

接收链路：读取器识别 appmsg-6 文件卡片 → 按账号、聊天和真实发送者登记引用 → 模型调用 `wechat_file_receive` → 核验电脑微信中的完整文件 → 复制至当前 DSH 工作区。不会自动下载尚未保存在电脑微信中的文件；缺失、同名不明确或摘要不一致时明确返回失败，继续处理其他消息。

发送链路：`wechat_file_send` 核验工作区相对路径 → 暂存不可变文件副本并登记传输记录 → 独立后台队列调用原生发送 → 核对新的 appmsg-6 消息及非零服务器回执。排队及原生接口接受请求均不等于送达。不确定的提交不会自动重复发送，等待回执时不占用文字发送锁。

单文件上限为 50 MB。运行记录与发送副本位于程序数据目录的 `workspace/state/files/`；接收副本位于当前工作区的 `.wechatagent-files/incoming/`，分别按账号、聊天、发起者和消息编号存放。文件内容不会自动执行。同一群仍共享其工作区，引用权限并不替代 DSH 对工作区工具的权限控制。

## 原生构建依据

原生适配只针对微信 **4.1.10.27**。静态核对其文件消息工厂 `0x1C4CE70`、构造函数 `0x18EEDC0`、所有者函数表 `0x84F96B8` 和消息函数表 `0x84F9748`。通过真实构造函数初始化对象，设置收件人、文件路径、文件名及长度，消息类型为 49、子类型为 6。版本、工厂指令、函数表、账号、暂存目录、大小与文件摘要均需通过校验。

构建清单的文件能力标记为 `nativeFiles: appmsg-6-factory-v1`。旧组件未提供文件能力时拒绝发送，不替换为路径、链接或表情。更新原生组件后须重新启动匹配微信。

2026-10-22 已向用户授权的“文件传输助手”发送一次无个人信息的测试文件，取得新的 appmsg-6 消息和服务器回执。接收、排队发送及 DSH 原生搜索另通过真实 DSH 运行时的隔离验证。开发机记录位于 `state/assistant-mode-20261022/file-live-verification.json` 和 `file-real-verification.json`；这些运行记录不属于公开源码或安装器内容。
