# DSH 输入批次去重与恢复

微信消息收到后，桥接会先保存本批消息 ID、提示正文、批次 ID 和表情编号映射，再请求 DSH。连接中断或桥接重启后继续使用这份快照，不因为表情池、联网状态或新消息变化重新生成同一批输入。后来收到的消息排在原批次之后，真实消息 ID 不同的相同文字分别处理。

DSH 将批次 ID 写入实际接收的用户消息事件。接收前断线可以重试；接收后断线则让已有任务在原时限内完成并缓存结果，下一次连接取回原结果。压缩会话或重启后仍可通过事件记录识别已接收批次，不重复追加用户输入。

已经接收、最终执行失败或超时的批次不会无限重投。桥接记录“该批未回复”的状态并继续处理后续消息；尚未提交给 DSH 的连接错误不会被当作已处理而丢弃。此机制不会取消正常的 DSH 内部模型请求重试，也不会把格式校正或图片降级误当成一条新的微信消息。

模型输出经过一次格式校正仍无效，或选择了未授权的表情时，也会终结该批，不发送异常内容；不会一直命中同一份无效缓存而堵住后续消息。

桥接快照位于当前账号的 `state/social-messages.json` 的 `pendingRequests` 字段，含本机聊天上下文，不应上传。任务确认、沉默或明确失败后清除；正常的微信发送回执仍由原发送队列管理。

更新插件后需要重新加载 DSH 桥接插件，并重启 WeChatAgent 后台服务。已有会话与历史不删除；历史中已经显示的重复输入不会自动清理。
