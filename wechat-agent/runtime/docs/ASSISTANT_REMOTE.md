# 微信远程助手

助手模式把微信作为 DSH 的任务入口。任务使用真正的 DSH Agent、工作区、工具、技能和原生权限；DSH 仍单独安装。电脑、匹配微信、DSH 和 WeChatAgent 后台需要保持运行，窗口可以收起到托盘。

任务进度文案可在“设置 → 助手设置 → 助手任务反馈 → 管理语录”中增删改，详见[自定义语录说明](ASSISTANT_FEEDBACK.md)。

## 首次设置

1. 在“设置 → 助手设置 → 助手模式管理员”选择自己的真实微信 ID 并保存。私聊始终只允许指定管理员；群聊管理员开关沿用原设置。
2. 在“聊天 → 设置此聊天”选择“助手模式”并保存。
3. 打开该聊天的“能力与权限”，选择 DSH 任务预设。默认是“微信助手”；也可选择 DSH 已有的 `standard` 等预设。预设的工具、第三方插件及技能继续在 DSH 中安装、管理。
4. 选择能力配置：“逐项授权”继续使用勾选列表；“使用 DSH 可用能力”使用所选助手 Agent 能访问的工具与技能，之后新增的可执行能力也会生效。两者都遵守 DSH 原生权限。旧配置保持逐项授权，不会自动扩大权限。
5. 按需要开启“微信文件收发”和当前聊天的“联网搜索”。审批默认在电脑端；可以单独勾选“允许指定管理员通过微信确认原生审批”。

人格只决定表达风格，任务操作受实际工具和权限控制。纯界面插件不会变成可调用工具。更换已有会话的 DSH 预设，会创建继承历史的续接会话并归档原会话；不会修改 `standard` 本身。

## 使用示例

直接发送明确需求，例如“检查当前项目的启动错误，修复后运行测试，把修改说明和报告发给我”。群聊需要按本群规则 @ 助手或使用唤醒词。

| 微信命令 | 用途 |
| --- | --- |
| `助手帮助` | 查看命令说明 |
| `助手能力` | 查看当前可用工具、技能、审批方式及任务限制 |
| `新任务 具体要求` | 明确开始一项新任务 |
| `任务列表` | 查看当前聊天最近任务；普通成员只查看自己发起的任务 |
| `任务状态` / `任务状态 T…` | 查看当前任务或指定任务的执行阶段 |
| `取消任务` / `取消任务 T…` | 请求取消；原生工具是否立即退出取决于 DSH 和相应插件 |
| `继续任务 T… 补充要求` | 在相同工作区继续已结束的任务；这是新的用户指令，不自动重跑旧命令 |
| `回答 Q… 答案` | 回答 DSH 原生工具提出的澄清问题；多个问题按提示提供 JSON |
| `工作区列表` | 管理员查看 DSH 已登记工作区 |
| `切换工作区 工作区编号` | 准备切换，返回一次性确认编号 |
| `确认切换工作区 W…` | 五分钟内确认；有活动任务时拒绝移动 |
| `批准 A…` / `拒绝 A…` | 指定管理员对当前聊天的一次原生审批作出决定 |

状态、取消、回答和审批走独立控制接口，不排在正在执行的模型任务后。任务会推送开始、等待审批、等待回答和必要的长时间运行状态；完成结果使用原来的可靠回复发送流程。

## 审批与身份

微信审批必须在本机为当前聊天启用，实际发起者也须是指定管理员。每次展示真实原生工具调用和一次性编号，有效期最多十分钟；批准只对这一次请求有效。操作无法完整展示、参数缺失、过期、权限收回或账号切换时，不会通过微信授予批准。DSH 自身拒绝审批的策略不会被改变。带特殊确认意图的原生提问仍由其原有确认流程处理。

群管理员模式关闭后，成员可以使用本群已授权能力。群内共用工作区和历史，文件、工具执行结果在群内可见；这不是每个成员独立的操作系统沙箱。普通成员只能通过控制命令管理自己的任务；管理员可以查看和取消本聊天任务。权限名单只能在电脑端更改。

## 长任务、调度和恢复

默认单任务三十分钟、二百次授权工具调用，可在每个聊天中调整为五至一百二十分钟、十至一千次调用。相同聊天串行执行，不同聊天可以独立进行；桥接中尚未开始的输入会持久保存。连续发送文字与附件时，会先等待一个短合并窗口，减少附件晚到造成的误判。文件已经收到与文件内容已经解析是两种状态；PDF、Office 等需要所选 DSH 预设提供解析技能或终端工具。

原生后台 job 绑定实际发起任务，成功结束通知静默处理，失败提醒和定时任务结果独立排队；原始终端输出不会自动群发，需要时再让助手查看结果。通过助手创建的 DSH 原生定时任务记录创建者；到期后仍验证账号、聊天、真实发起者和当前工具权限，并将结果放入独立通知队列。无法确定唯一发起者的定时批次拒绝执行；更新前创建、没有发起者记录的旧定时任务应重新创建。切换预设或工作区后，旧会话中的原生调度不自动迁移，需要核对并重新建立。

任务提交使用持久批次编号去重，短 HTTP 请求断开不会重新执行同一操作。DSH 重启时，执行中的任务标为“中断”，不会自动重跑可能已经发生的写文件、命令或发送操作；确认实际结果后使用“继续任务”补充新指令。尚未开始的排队任务在重新检查权限后可以继续。

数据保存在当前程序数据目录：

- `workspace/state/assistant-tasks/<账号标识>/tasks.json`：任务编号、状态、请求与结果，最多二百条。
- 同目录 `notifications.json`：原生 job、定时任务发起者绑定和待投递通知，最多二千条原生任务绑定、二百条通知；超过一天的未投递通知过期。
- 原来的 DSH 原生会话、文件传输缓存和微信数据位置不变。

普通关闭窗口仍收起到托盘；“退出应用”停止 WeChatAgent 后台及通知发送。DSH 中任务的结束方式继续受 DSH 原生生命周期约束。
